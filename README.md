# Ronin Agent

A self-hosted bash agent bridge for AI chat sites. A small Go server
executes shell commands; a userscript injected into ChatGPT, Claude,
Gemini, or DeepSeek extracts bash code blocks from the AI reply, runs
them through the server, and feeds the output back into the
conversation. The model becomes a pair-programmer on a real Linux box.

## Features

- Streaming execution - command output streams back to the chat as
  NDJSON, line by line, so long builds show progress live.
- Per-chat on/off toggle - enable the agent per conversation from the
  overlay pill.
- Layered security - catastrophic-command denylist, a confirmation gate
  for sensitive operations, and an optional read-only mode.
- Root confinement - commands run inside a configured project root;
  symlinks are resolved so they cannot escape it.
- Origin allowlist - only the supported chat origins may drive the
  server from a browser.
- Secure by default - the first run generates a random auth token.

## Quick start

Build and run the server:

    go build -o ronin .
    ./ronin -config config.json

On first run it writes a config.json (mode 0600) containing a randomly
generated token and exits. Edit it, then run again:

    {
      "port": 8080,
      "root": "/path/to/your/project",
      "allow_roots": [],
      "timeout": "5m",
      "token": "<auto-generated>",
      "read_only": false,
      "allowed_origins": ["https://chat.deepseek.com"],
      "ngrok": { "enabled": false }
    }

Then install userscript.js in Tampermonkey, Greasemonkey, or
Violentmonkey; open the overlay settings, set the Server URL and Token,
and run Test connection.

## Configuration

| Key               | Meaning                                                       |
|-------------------|---------------------------------------------------------------|
| port              | HTTP listen port (default 8080)                               |
| root              | Default working directory for commands                        |
| allow_roots       | Extra permitted roots. Empty = confine to root only           |
| timeout           | Per-command timeout, e.g. 5m                                  |
| token             | Bearer token required on /exec, /info, /ngrok                 |
| read_only         | When true only read commands are allowed                      |
| allowed_origins   | Browser origins allowed to call the server                    |
| ngrok             | Optional tunnel: enabled, authtoken, domain, data_dir         |

## Security model

Three layers, evaluated in order:

1. Denylist (always rejected) - a small catastrophic set: fork bombs,
   recursive deletes on the filesystem root, filesystem-format
   utilities, and power-off/restart verbs. Deliberately narrow so normal
   work is never blocked.
2. Confirmation gate - sensitive operations (privilege escalation,
   package managers, service control, containers, firewall, mounts,
   destructive git operations, block-device writes) return a
   confirm_required response and only run after the user approves.
3. Read-only mode - a first-word allowlist. Redirects to the null device
   and descriptor dups are permitted; writing to a real file is not.

Commands are confined to root (or allow_roots) with symlinks resolved.
Browser callers are restricted to allowed_origins.

The server is only as safe as its token. Never expose it publicly
without one, and prefer running it behind a tunnel you control.

## Building from source

Requires Go 1.22+.

    make build      # build for the host
    make test       # go vet
    make cross      # build the six release targets into dist/

## Supported platforms

linux, windows, and darwin, each on amd64 and arm64, are built by the
release workflow in .github/workflows/release.yml.
